= 既知の問題
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
ここでは、このリリースの製品の正常な使用に支障をきたす可能性がある既知の問題について説明します。

現在のリリースに影響する既知の問題は次のとおりです。



[[volumes-remain-attached-after-upgrading-from-trident-22-10-or-earlier]]
== Trident 22.10以前からのアップグレード後もボリュームは接続されたままになる

この問題は、ボリュームがアタッチされている状態で、Trident 22.10以前からTrident 26.10へ直接アップグレードするお客様に影響します。Trident 23.01以降からのアップグレードは影響を受けません。

アップグレード後、影響を受けるボリュームがデタッチされない場合があります。ReadWriteOnce（RWO）ボリュームを使用するPodは別のノードに移動できず、マルチアタッチエラーを報告する可能性があります。PersistentVolume（PV）の削除もハングする可能性があります。

この問題を回避するには、古いボリューム接続が存在するノードで、そのボリュームの `globalmount`ディレクトリから残留している `volumePublishInfo.json`ファイルを削除してください。



[[volumesnapshots-not-reaching-readytouse-state]]
== VolumeSnapshotsがReadyToUse状態に到達しない

[WARNING]
====
 `csi-snapshotter`サイドカーには既知の問題があります。すべてのKubernetesバージョンにおいて、VolumeGroupSnapshots `v1beta1`がVolumeSnapshotsの `ReadyToUse`状態への到達を防ぎます。

====
回避策は 2 つあります：

. VolumeGroupSnapshots CRDを削除してVolumeGroupSnapshotsを無効にし、Tridentを再インストールします。
. VolumeGroupSnapshots `v1beta2`および `snapshot-controller`バージョン8.4.0以降をインストールしてから、Tridentを再インストールしてください。VolumeGroupSnapshotsはKubernetesバージョンv1.34より前では機能しません。




[[restoring-restic-backups-of-large-files-can-fail]]
== 大容量ファイルのResticバックアップのリストアが失敗することがある

Restic を使用して作成された Amazon S3 バックアップから 30 GB 以上のファイルを復元すると、復元操作が失敗する可能性があります。回避策として、データ ムーバーとして Kopia を使用してデータをバックアップします (Kopia はバックアップのデフォルトのデータ ムーバーです)。参照 https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-protect-apps.html["Trident Protectを使用してアプリケーションを保護する"^]手順についてはこちらをご覧ください。
